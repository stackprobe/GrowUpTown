# Grow Up Town

C# / Raylib の3D見下ろし型・町建設シミュレーションです。外部画像やモデル不要のプロシージャル描画で、住宅、商業地、工業地、公園を配置できます。

## デザインの縮尺方針（今後の制作・修正時に参照）

- デフォルメによる多少の大きさの不整合は許容しますが、町全体で自然に見える縮尺を優先します。新規施設や外観を追加・修正するときも、通常の住宅・商業地・工業地・公園・走行車を基準にしてください。
- 大きな敷地や建物でも、ドア・窓・車両・ベンチ・遊具・看板などを敷地に比例して拡大しないでください。特にスペシャル施設が、巨大なトラックやドアを持つ「巨人用の施設」に見えないように注意します。広さは部品の数や配置、建物の構成で表現します。
- デザインの縮尺を調整するときは、既存の敷地サイズ・施設の機能・費用などの仕様を維持します。木の根元や車輪などの接地、部品同士の重なりも確認してください。
- 単体の見栄えだけで判断せず、通常の建物や走行車と同じ画面に並べ、普段のカメラ角度と拡大率で比較します。30年解放の3施設は `GROWUPTOWN_SPECIAL_PREVIEW=scale`、35年解放の3施設は `GROWUPTOWN_LANDMARK_PREVIEW=scale`、40年解放の3施設は `GROWUPTOWN_LARGE_SPECIAL_PREVIEW=scale`、45年解放の3施設は `GROWUPTOWN_GIANT_SPECIAL_PREVIEW=scale`、50年解放の3施設は `GROWUPTOWN_MEGA_SPECIAL_PREVIEW=scale`、55年解放の3施設は `GROWUPTOWN_NINE_CELL_PREVIEW=scale`、60年解放の3施設は `GROWUPTOWN_TEN_CELL_PREVIEW=scale` と `--smoke-test` で比較でき、各施設の16種類のプレビューでも確認できます。

### スペシャル施設の描画と負荷

スペシャル施設は、窓枠・反射・壁材の目地、屋根の継ぎ目、石畳を起動時に生成した共通テクスチャで描画します。外壁は海辺・庭園・都市・産業の4系統で材質が変わり、既存の16形状と組み合わせます。屋上の縁取りと小型設備、外周の植栽帯、敷地内の歩行動線で、通常の倍率でも建物と広場に情報が残るようにしています。設備や植栽の部品サイズは敷地に比例して拡大しません。

テクスチャは128×128を6枚だけ共有し、ミップマップ込みで約0.5 MiBです。窓ごとの立方体を外壁4枚の面へ置き換え、窓数に比例して描画頂点が増える処理をなくしています。ミップマップとトリリニアフィルタで遠景のちらつきを抑え、終了時にGPU資源を解放します。外部画像・モデルや毎フレームの画像生成は不要です。

負荷比較（Intel UHD Graphics、1440×900、MSAA 4x、カジノ16形状、上限FPSを外して360フレーム×2回）では、変更前8.49～8.95 ms/frame、変更後7.03～7.41 ms/frameでした。この場面の描画時間は約17％減少しています。施設の組み合わせやPCによって実際の値は変わります。

## Visual Studio 2022 で起動

1. Visual Studio 2022 **17.8 以降**と「.NET デスクトップ開発」ワークロード、.NET 8 SDK を用意します。
2. `GrowUpTown.sln` を開き、NuGet パッケージの復元を待ちます（初回はネット接続が必要です）。
3. `GrowUpTown` をスタートアッププロジェクトにして F5 で開始します。

Windows x64 向け。日本語表示に Windows のメイリオ、なければ游ゴシックを使用します。システムフォントの配布は行いません。

## コマンドライン

```powershell
dotnet build GrowUpTown.sln -c Release
dotnet run --project GrowUpTown.csproj -c Release
dotnet run --project GrowUpTown.csproj -c Release -- --self-test
dotnet run --project GrowUpTown.csproj -c Release -- --smoke-test
```

`--self-test` は描画なしで経済・接続・保存等を検証します。`--smoke-test` はウィンドウを8フレーム描画して終了します。環境変数 `GROWUPTOWN_SCREENSHOT` にファイル名（例：`smoke-test.png`）を設定すると終了前にスクリーンショットを出力します。保存先はセーブデータと共通です。パスを指定した場合もファイル名部分のみを使用します。

## シミュレーションのルール

### 鉄道（40年1月解放）

- 左側のメイン建設メニューから「線路」「駅」を直接選択できます。ショートカットは線路がB、駅がNです。線路は1マス100円・維持費3円/月、駅は2×2マスで4,800円・維持費100円/月です。
- 線路は道路と同じように連続配置でき、水域に敷設できます。直線の線路の両脇が水域になると鉄道橋になります。
- 道路に線路、または線路に道路を重ねると踏切になります。踏切上はアスファルトとレールのみで、枕木・バラストは描画しません。道路・鉄道の接続はそれぞれ維持され、撤去すると両方を除去します。
- 線路自体に周辺効果はありません。異なる2駅以上を線路で結ぶと、各駅から5マス以内の住宅の住環境が＋10、道路接続済みの商業施設の商業税収が＋20％になります。同じ鉄道効果は重複せず、既存施設の効果とは加算されます。住環境の既存上限は＋25です。
- 駅の新規設置には、2×2の空き地の上下左右いずれか1辺に、その辺と平行な直線線路が2マス並んでいる必要があります。両方の線路が直線であることが条件で、終端・カーブ・三叉路・十字路は不可です。線路の形が直線の踏切は利用できます。駅舎に向かう枝線は不要で、駅を置いても隣の線路の形は変わりません。
- ホームは線路2マスのある辺、駅入口は道路に面する辺に配置します。線路や道路が複数辺にある場合はホームと入口を反対側に配置できる組み合わせを優先し、横側の道路には側面入口を設けます。道路がない場合も設置でき、入口はホームの反対側になります。ホームと入口の向きは建設時に固定して保存します。
- 駅構内を経由する路線の接続判定は維持します。駅同士を隣接させるだけでは効果はありません。線路切断・駅撤去時に効果を再判定します。既存の駅は新しい設置条件を満たさなくなっても残ります。
- 線路の形は隣接する線路だけで決まります。三叉路は分岐可能、十字路は分岐不可・直進のみの平面交差です。列車の経路と駅間の接続判定もこのルールに従い、十字路で縦横の路線はつながりません。地面には砂利の粒・陰影・色むらのあるバラストを使用します。
- 線路には3両編成の列車が走ります。3両全体がホーム中央に収まる位置で約3秒（1倍速時）停車し、その後発車します。終端には赤白の車止めがあり、その手前で約2秒停車してから、車体の向きを変えずに反対側の運転台を先頭にスイッチバックします。十字の平面交差で他の列車が通過中の場合は手前で待ちます。
- 踏切は通常開いています。列車が近づくと赤ランプが交互に点滅し、遮断機が下がります。自動車は手前で停止し、列車の後部が通過して遮断機が上がると再発進します。踏切内に車が残っている場合は、列車も手前で待ちます。
- 列車・自動車・踏切のアニメーションはゲーム速度に連動し、一時停止中は停止します。車と同様に表示範囲内の演出で、列車位置は保存しません。建設・撤去操作から独立したタイマーで約2秒（1倍速時）ごとに出現を確認し、実際に画面内にある線路の中央寄りを優先します。画面に列車がいない場合は画面外の列車に妨げられず補充します。3両が収まる線路が必要で、開放中の踏切や他の列車と重なる位置には生成しません。表示範囲の路線ごとに1編成、同時表示は最大64編成です。列車の前後の線路編集では経路を再計画し、列車が乗っている線路の撤去時には列車を除去します。
- 駅は田園・海辺・都市・レンガの4系統×4形状の計16種類です。周囲の公園・住宅・水辺・商業・工業を考慮し、近隣駅で未使用のデザインを優先します。全種類が使用済みの場合は使用数の少ないものを選びます。外観と向きは建設時に固定され、保存・読込でも変わりません。
- 描画確認：`GROWUPTOWN_RAIL_PREVIEW=1` を設定して `--smoke-test` を実行すると、16種類の駅・踏切・鉄道橋を表示します。
- `GROWUPTOWN_RAIL_PREVIEW=junctions` では三叉路4方向・十字路・駅沿いの直線とバラストを拡大表示します。
- `GROWUPTOWN_RAIL_PREVIEW=stations` では、ホーム4方向と道路側の入口を16種類の駅で確認できます。
- `GROWUPTOWN_TRAIN_PREVIEW=5` と `--smoke-test` では列車の踏切通過中、`13` ではホーム停車中、`24` では終点停車中、`27` ではスイッチバック後、`0` では通常の踏切開放状態を確認できます。
- `GROWUPTOWN_TRAIN_PREVIEW=auto` では、操作・手動生成なしで8秒間進めた列車の自動出現を確認できます。

### 森林

- メインの建設メニュー「森林」、またはGキーで選択します。鉄道と同じ40年1月に解放され、1×1マスへの配置・ドラッグでの連続配置ができます。設置費420円、維持費18円/月、Lv.1固定です。
- 周囲3マス（縦横の距離の合計）の住宅の住環境を＋15改善します。公園の道路接続時＋10より高く、森林は道路接続不要です。複数の森林・ほかの施設の効果は加算され、住環境の上限＋25は維持します。
- 公園の通路には接続せず、公園同士や道路・建物への接続を中継しません。
- 広葉樹・針葉樹・白樺・混交林の4系統×4配置、計16種類の外観があります。近隣の使用数を考慮し、隣接する森林と異なる柄を優先します。配置方向・樹高・色味にも変化があり、外観は設置後も保存・読込後も維持されます。
- `GROWUPTOWN_FOREST_PREVIEW=1` と `--smoke-test` で16種類と密集配置を確認できます。`menu` では建設メニューも表示します。

解放前も左の項目は残り、名称・金額を「？」「¥？」で表示します。項目は無効になり、クリック・ショートカットキー・建設操作からは選択・設置できません。スペシャルの選択ウィンドウも30年まで開けません。大公園・スーパーマーケット・物流センターはスペシャルから30年、巨大水族館・大観覧車・ロボット研究所は既存スペシャルの5年後となる35年、線路・駅・森林はメイン建設メニューから40年に解放されます。解放月に自動で通常の名称・金額と操作が戻ります。道路などの通常施設、土地購入、撤去は開始時から使えます。

保存した年月で解放状態を判定します。以前のセーブに解放前の建物が存在する場合、その建物は保持され、稼働・成長・撤去できますが、新規建設は解放を待つ必要があります。新しい町では再び封印されます。

`GROWUPTOWN_UNLOCK_PREVIEW=1`・`10`・`12`・`15`・`20`・`30`・`40`・`50` と `--smoke-test` で各年のメニュー表示を確認できます。既存の建物外観プレビューは、全施設が解放される50年1月から開始します。

画面右側の「今、町に必要なもの」に、住宅・職場・発展条件の案内を常時表示します。建設・撤去・月の経過・読込に応じて更新されます。

- 住宅がない、または職場の発展に必要な人口を収容できない場合は、必要な追加定員と住宅建設を案内します。住宅の空きが少ない場合も表示します。
- 労働人口より雇用枠が少なければ職場不足です。商業地・工業地の追加を案内します。
- 労働人口が雇用枠の55%未満なら、商業・工業の発展に不足する労働者数を表示します。住宅定員が十分なら人口増加を待ち、不十分なら通常住宅を増やす案内になります。
- 道路未接続の建物や幸福度60未満も案内します。商業と工業は共通の雇用条件で判定します。

数値は既存の町の集計値を使い、画面外の区画についても通常のシミュレーションと同じ更新タイミングになります。

- 最初から住宅4棟、商業地、工場、公園、外部接続道路のある小さな町で始まります。所持金は16,000。
- 道路は上下左右で接続します。最初の町の西側入口 **(0, 12)** まで続く道路に、建物が隣接していると稼働します。拡張後も入口は同じ場所です。斜め接続は無効。赤枠は道路未接続です。
- 道路の絵は現在の隣接道路に合わせます。直角の2方向はカーブ、向かい合う2方向は直線、3方向はT字路、4方向は十字路です。隣を建設・撤去すると自動で切り替わります。16接続パターンの共通テクスチャを使用します。
- 通常5秒で1か月進みます。住宅はレベルごとに24人、商業地は16人、工業地は32人の雇用枠を持ちます。住民の55%が労働人口です。
- 雇用と住宅に空きがあり幸福度が保たれると、1棟につき最大4人/月が入居します。道路が切れた住宅や幸福度の低い町からは住民が減ります。
- 幸福度60以上で十分な入居・就業条件を6か月連続で満たすと、建物が自動で成長します（最大レベル3）。人口の目標は500人です。目標達成後も続けられます。
- 公園は距離3以内（縦横の合計）に好影響、工場は悪影響を与えます。高税率・失業・借金も幸福度に影響します。
- 税収は住民税と稼働率に応じた商業・工業税。道路と建物には毎月の維持費がかかります。撤去に返金はありません。
- 資金がマイナスでも時間は進みます。ゲームオーバーはありませんが、建設には費用が必要です。初期の町は黒字で運営できます。
- これは基本動作を備えたシミュレーションです。電力・水道・個別住民の経路探索は対象外で、車は道路上の演出です。

## super建築物

いずれもレベル1で建設し、条件を6か月連続で満たすと最大レベル6まで成長します。通常の建物の最大レベルは3のままです。

| 建築物 | 建設費 | 1レベルあたりの入居定員 | 1レベルあたりの雇用 | 1レベルあたりの維持費/月 |
|---|---:|---:|---:|---:|
| super住宅商業地 | 4,280円 | 96人 | 64人 | 52円 |
| super工業地 | 3,600円 | — | 128人 | 56円 |

## 公園の外観と接続

公園には林・花壇・噴水・遊具・ピクニック・植え込みの6種類の装飾があります。上下左右に公園を並べると芝生と園路がつながり、共有する境界の縁石がなくなります。隣が道路や大公園の場合も、その方向へ園路を伸ばします。道路自体が入口につながっていなくても園路の見た目は接続します。斜めには接続しません。

配置場所と町のシードで外観を決め、上下左右の公園が増減すると園路と装飾が変化します。同じ隣接状態に戻すと元の外観に戻ります。隣の道路の追加・撤去では園路だけが変化し、装飾は変わりません。月の経過でも変わらず、既存セーブにも対応します。表示範囲の公園だけを軽量な図形で描き、描画のたびに全公園を探索したり画像を再生成したりしません。

公園・大公園が上下左右につながっていれば、そのどこかが最初の入口へ続く道路に面することで、ひと続きの公園全体を道路接続済みとします。途中の公園や道路を撤去すると接続を再判定します。公園経由の接続は公園専用で、住宅・商業地・工業地や別の道路網へは伝わりません。

通常公園の住環境効果は距離3以内に接続時＋10、未接続時も30％の＋3です。大公園は距離5以内に接続時＋20、未接続時＋6となり、占有16マス分を重複加算しません。全体の住環境上限＋25は共通です。大公園の外観・向きは接続状況が変わっても固定されます。

## 水域と橋

水域は隣り合うマスでつながり、細く並べると川、広く並べると池になります。岸は陸との境界だけに描画します。道路接続なしで距離3以内（縦横の合計）の住宅に1マスあたり住環境+10の効果があり、公園等を含めた上限は+25です。

道路の接続が東西の2方向で南北が水域、または南北の2方向で東西が水域なら、自動で橋になります。後から道路・水域を追加・撤去した場合も更新されます。水域の上に道路を引くこともできます。幅の広い川では各道路マスの両脇に水域を並べると、欄干と橋面が連続する長い橋になります。水域上に建設した道路を撤去すると空き地になります。橋に追加料金・追加維持費はありません。

水域は画面付近だけをまとめて描画し、マスごとの画像生成やモデル生成は行いません。Version 3の既存セーブをそのまま読み込めます。
水面には、ゆっくり流れる波の筋と緩やかな明暗のうねりをGPUで描画します。水面は1マス1枚の面のままで、毎フレームの地形再生成や画像転送はありません。波は区画の境界でも連続し、ゲームの停止・倍速に連動します。
水面は地面より0.16マス低く、陸との境界には幅0.14マスの短い斜面があります。橋の下も地面を抜いて水面を通します。画面付近の区画ごとに地形データを保持し、建設・撤去時には影響する区画と境界付近の隣接区画だけを更新します。

## 保存

車は初期道路だけでなく、追加した道路・橋・入口につながっていない道路にも表示され、接続に沿って曲がり、行き止まりでは折り返します。孤立した1マスでは停車表示になります。車は描画用の演出で、現在の道路データには混雑率がないため一定の発生頻度です。カメラ付近だけで生成・更新し、同時表示は最大1,024台。停止・倍速に連動し、車の状態は保存しません。

保存先は DEBUG 時が `GrowUpTown.sln` と同じフォルダー内の `SaveData/city.json`、非 DEBUG 時（Release）が実行ファイル `.exe` と同じフォルダーの `city.json` です。起動時の作業フォルダーには依存しません。スクリーンショットと自己テスト用の一時ファイルも同じ保存先を使用します。`SaveData` は必要時に自動作成します。以前の `%LOCALAPPDATA%\GrowUpTown\city.json` を使う場合は、新しい保存先に手動でコピーしてください。

F5で1スロットに上書き保存します。自動保存はありません。新しい町を始める際は確認画面を表示します。既存の保存ファイルは新規開始では消去しません。

土地と画面外の発展状態を保存するため、保存形式を **Version 3** に更新しました。旧形式（Version 1・2）は読み込めません。新しい町を始めてF5で保存すると、新形式で上書きされます。

## 土地の拡張と画面外の町

最初の土地は24×24マスです。所有地の上下左右に隣接する同サイズの土地を、初回 **1,000,000円**、2回目 **1,500,000円**、3回目 **2,000,000円**、4回目 **2,500,000円** と、購入するたびに50万円ずつ上がる価格で購入できます。最初から所有する区画は購入回数に含めません。購入失敗・キャンセルでは価格は上がりません。保存・読込後も購入済み区画数から次の価格を引き継ぎ、既存のセーブにも適用します。斜めだけの接続は購入できません。購入済みの土地は売却できません。

区画数にゲーム上の固定上限はありません。ただし座標の整数範囲とメモリ等の実行環境には制約があります。カメラ付近を原点にして描くため、遠い土地でも描画の精度を保ちます。描画は画面付近の区画だけを対象にし、空き地の自然物は座標から再生成します。画面外の建物データはメモリ内で圧縮します（ディスクへの逐次退避ではありません）。

画面付近は毎月発展し、画面外は最大12ゲーム月ごとの分散更新、または再表示時に経過分を反映します。その時点の町の条件で経過月を計算する近似方式なので、常時表示した場合と完全に同じ結果にはなりません。画面外の税収・維持費は直近の集計値から毎月計上し、再表示時に二重計上しません。道路の接続判定は建設・撤去時に更新します。

## 階ごとの外観

- 面が向いている方向の道路、公園、工場、周辺建物の高さや空き地を参考にします。

## 構成

### 配置後の接続・周辺効果のバックグラウンド更新

通常プレイでは、建設・撤去時に道路・鉄道接続と周辺効果の再計算を予約します。最後の編集から約0.35秒経過、または更新予約から約2秒経過すると、町のコピーを使って別スレッドで計算します。連続配置の予約はまとめ、同じ町で計算ジョブを同時に複数走らせません。更新中は接続表示・住環境・周辺支援・収支集計に一時的な遅れがあり、時間停止中やメニュー表示中でも実時間で処理を進めます。以前の各施設説明にある撤去・道路切断時の効果更新も、この更新の完了時に反映します。

コピーの作成と結果の反映は区画単位に分け、1フレーム約2msを目安に進めます（1区画分の処理は途中で中断しないため、厳密な上限ではありません）。計算中に建設・撤去された場合は古い結果を破棄し、最新の町を再計算します。反映するのは接続・周辺効果だけで、人口・レベル・外観・資金・ゲーム月をコピーの時点へ巻き戻しません。

配置時に発展を同期するのは編集対象の区画のみです。画面外の圧縮データはコピー側で展開し、必要な再圧縮も計算スレッド側で行います。通常の毎月発展、税率変更、保存・読込は従来の処理を使うため、それらの操作では別途処理時間がかかることがあります。

更新待ちでも保存できます。配置内容と進行状況を保存し、読込時に接続・周辺効果を再計算します。読込・町の作り直し・終了時は以前のジョブを切り離し、別の町に結果を適用しません。シミュレーションの直接呼出しは既定で同期更新、通常プレイは `EnableDeferredUpdates()` と毎フレームの `ServiceBackgroundUpdates()` を使用します。

`BackgroundNetworkTests.cs` で予約の統合、計算中の編集、圧縮区画、保存、進行状態の保持、従来方式との収束結果を検証します。4区画の町への24回の配置で、配置処理のみの合計は約1,301ms（同期）／約0.4ms（遅延）でした。この値はローカル測定で、後者にはバックグラウンド再計算の時間を含みません。`GROWUPTOWN_BACKGROUND_PREVIEW=1` と `--smoke-test` で通常画面の更新経路を確認できます。
